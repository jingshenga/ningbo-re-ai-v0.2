# NAS 隔离业务负载 30 分钟验收

日期：2026-11-10。执行目标为 DXP4800；测试通过 `nas-lan` 直连。

## 环境与边界

- 独立 PostgreSQL 17、API 和证据卷；Compose 网络设为 `internal`，没有宿主机端口。API 与数据库各限制 1 CPU、512 MiB。
- API 容器使用 NAS 当前运行镜像作为依赖层，并只读挂载当前工作区 `app/`；数据库从 `sql/001` 至 `sql/005` 初始化。生产 Compose 项目、数据卷和服务没有参与测试。
- 测试器只允许访问 Compose 内部 `api:8000` 或 loopback。HTML 和挂牌编号均为合成内容；`nb.ke.com` 链接只作为数据字段写入隔离库，网络无外连，不请求贝壳或安居客。
- 在线采集总开关、贝壳和安居客来源开关在测试期间均为关闭。

## 结果

- 运行 1,800.61 秒，4 并发；完成 **10,199** 个“样本导入→待审列表读取→人工审批→挂牌查询→价格历史查询→健康指标查询”工作流，共 **61,194** 次 API 请求，错误 **0**。
- 各端点 10,199 次，P95：导入 186.54 ms、待审列表 165.52 ms、审批 272.59 ms、挂牌 222.71 ms、价格历史 165.83 ms、健康指标 123.76 ms。
- 数据库对账：候选 10,199（approved 10,199、pending 0），挂牌 10,199，价格历史 10,199。健康指标 API 的 beike approved/listing 均为 10,199，anjuke 均为 0；两来源和全局在线开关均为 `false`。
- 原始合成证据 10,199 个 gzip 文件、3,262,751 字节。资源采样记录 API/DB 各 284 个点：峰值 CPU 分别 106.37% 和 108.60%，峰值内存分别 65.69 MiB 和 65.15 MiB。CPU 超过100%反映单核限额下的采样口径；数据库 CPU 是主要压力，内存远低于512 MiB限制。
- 原始 JSON 和资源样本见[测试报告](reports/LOAD_TEST_2026-11-10.json)与[资源采样](reports/LOAD_TEST_2026-11-10-resource-samples.csv)。NAS 两个文件的 SHA-256 与工作区副本一致。

## 预检与清理

预检发现旧 API 镜像创建的新命名卷不允许 UID 10001 写入，以及不同运行批次复用合成挂牌编号会命中旧候选。仅修正隔离卷属主，为脚本增加每轮随机编号及首错停止；4 并发 10 秒预检完成 63 个工作流、378 请求、0 错误。随后重建空白隔离卷再执行正式30分钟测试。

测试后定向删除隔离容器、PostgreSQL与证据卷、internal 网络、临时源码、随机密钥和报告临时文件；保留经哈希校验的工作区报告副本。生产 API/Worker 仍运行，PostgreSQL healthy；生产数据库和数据卷未改。

本结果只覆盖合成负载、1 CPU/512 MiB 的隔离资源与本轮 API 工作流，不是生产 SLO、生产容量承诺或真实房源数据质量验收。P0-08 仍待正式证据/备份留存期限确定和 UGREEN 项目页视觉核对。
