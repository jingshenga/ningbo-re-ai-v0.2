# 关键设计决策记录（ADR简版）

### ADR-001：先采集方案，未来才可能授权数据（2026-11-09）
决定：贝壳、安居客在当前设计中为`public_page_collection`；保留`licensed_api`枚举和统一来源字段，未来切换无需重建房源主数据。理由：当前没有授权接口，用户希望先通过许可范围内的采集与数据积累启动。约束：平台访问许可、robots和商业使用权并不随技术实现自动获得。

### ADR-002：原始页面 → 待审候选 → 正式挂牌（2026-11-09）
决定：采集器不直接更新`source_listings`；解析候选和证据归档后，经人审确认才更新挂牌及价格历史。理由：网页推荐模块、动态渲染、多个价格和解析器布局失效很容易制造假降价。

### ADR-003：来源房源ID独立，跨源关联是候选（V0.1延续）
决定：使用(`source`,`source_listing_id`)约束同源去重。不同平台相似房源必须保留`property_matches.candidate`和证据，不自动视为同套。

### ADR-004：低配NAS控制并发、组件拆分（V0.1延续）
决定：初期FastAPI+PostgreSQL+单Worker，ASR/OCR可选，抖音DTK独立部署。理由：16GB N100优先保证数据库稳定性。

### ADR-005：可追溯而非“万能AI估值”（2026-11-09）
决定：无可靠同类可比与成交证据时只给机会线索，不报确定的最低价、实际成交价或推荐收益。

### ADR-006：跨平台挂牌价差只生成待核实候选（2026-11-10）
决定：贝壳与安居客只有在同小区、同户型、面积差不超过5%时才比较挂牌单价；价差达到10%才生成机会信号，按`(高单价-低单价)/低单价`计算。两端挂牌保持独立，候选显式待核实，不自动认定同套或可成交价格。理由：避免跨平台价格差异被误读为已确认同一房屋或真实议价空间。该规则已本机实现并通过离线测试，尚未NAS验收。

### ADR-007：近似或上下限建筑面积必须人工核验（2026-11-12）
决定：如“100㎡左右”“100㎡以上”“建筑面积在100㎡左右”“参考/估算/预估100㎡”，解析器将`area_sqm`留空，保留数值候选和完整原文证据，添加`non_exact_area_sqm`告警，并令候选处于待人工审核状态。精确陈述“建筑面积为100㎡”仍可解析为100。理由：近似值和区间边界不能安全地当作精确建筑面积。该口径已由用户确认；现有解析器、页面提交API和样本评估器均按此执行。ASCII/全角加号及常见不等式符号也按范围边界处理，保留候选和证据并待审。


### ADR-008：非精确挂牌价须人工核验（2026-11-12）
决定：带近似或上下限限定的挂牌报价不作为精确挂牌价写入；解析结果保留金额候选与来源quote，添加`non_exact_asking_price`并保持待审。上下限文字及数学不等式符号均视为限定；精确报价仍按原规则处理。理由：不把估算值、区间端点或边界值当作确定报价。解析器、提交API和样本评估器按此契约验证。
