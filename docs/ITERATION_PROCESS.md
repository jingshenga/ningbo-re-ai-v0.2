# 目标驱动持续开发的工作方法

## 每轮操作

1. 使用同一个项目或Git仓库保存全部源码，不仅保存聊天记录。
2. 在项目指令中加入 `prompts/PROJECT_INSTRUCTIONS_SHORT.md` 的文本（如果平台支持较长项目指令，也可以使用 `docs/MASTER_DEVELOPMENT_PROMPT.md`）。
3. 把工程文件和 `AGENTS.md` 作为代码事实来源；最新 `docs/PROJECT_STATUS.md` 和 `docs/GOAL_STATE.json` 表示本轮真实进度。用户不需要每次重述业务背景。
4. 给代理发送 `prompts/NEXT_ITERATION.md`。如果有具体本轮目标，直接替换“本轮优先目标”。
5. 代理在本轮必须实际提交文件变更，说明测试、未验证的环境依赖与风险；根据证据修改状态，未经NAS联调不得标成“已部署”。
6. 保存下一版压缩包和变更记录；必要时同步至私有Git仓库，以便回滚。

## 任务状态准则
- `todo`：未开始；
- `in_progress`：有代码进行中，但未达到验收；
- `implemented`：代码已实现且相关本地测试通过；
- `verified_on_NAS`：在真实NAS+数据库/第三方依赖完成端到端验收；
- `blocked`：存在权限、样本、设备等明确阻塞条件。须记录可执行的替代任务。

## 绝不省略
- 备份；迁移脚本；API/版本文档同步；真实与模拟数据区分；数据来源用途与权限检查；错误及失效状态；主要测试和未执行测试。

## 常用指令示例

**自动选择下一任务**：
> 请按 AGENTS.md 和 ROADMAP.md，在没有环境阻塞的前提下选择P0最高价值待办，直接实现、测试、更新状态并交付更新源码。

**采集器专攻**：
> 以两个来源各20份合法使用的保存HTML样本为基准，开发对应解析器，不改价格模型，给出准确率/覆盖率，自动写候选不允许直接写正式房源。

**NAS联调**：
> 我在NAS上执行了这些命令并提供日志，请针对日志定位启动/迁移错误，最小修改并给出重试步骤，不破坏旧数据。
