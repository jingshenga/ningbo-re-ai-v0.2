# 离线挂牌链接发现

`scripts/discover_listing_urls.py`从操作者本地保存的列表页HTML中提取同来源、可识别稳定ID的详情链接；脚本不会请求来源网站。

```bash
python scripts/discover_listing_urls.py \
  --source beike \
  --page-url 'https://nb.ke.com/ershoufang/' \
  --html /path/to/operator-saved-list-page.html
```

可用`--seen-ids`指定每行一个已发现ID的UTF-8文本文件，过滤之前发现的挂牌；该文件必须是普通文件，最多读取2,000,000字节，超限、非UTF-8或不符合所选来源数字ID长度的内容会拒绝。空行会忽略，首尾空格会裁剪。也可改用`--state-file /path/to/state.json`在本地保存来源、已发现ID、已访问页和下一页地址；第一页仍传`--page-url`，后续快照可省略该参数以恢复状态中的下一页地址。状态文件上限2,000,000字节、拒绝符号链接并原子替换；校验来源一致、挂牌ID符合来源格式、历史/下一页地址仍在允许主机且不带query/fragment。状态路径必须与HTML输入为不同文件；同路径和硬链接别名均在读取前拒绝，避免覆盖快照。不自动访问或下载页面。JSON结果按页面顺序输出ID去重后的链接、可识别的`rel="next"`下一页路径和警告。

状态文件同时保留最近尝试页、累计失败次数和最近错误类型；HTML快照读取/解码/校验或链接解析失败时，未访问的失败页本身会成为待重试游标（包括首次页），修复本地输入后可省略`--page-url`沿同页续接；若操作者显式重放已访问页且失败，则只记录该次错误，保留现有游标，避免把已访问页写成回环。成功后清除最近错误类型。state-file/seen-ID辅助输入错误会给出对应诊断，不会误标为页面失败。结果JSON先写出并刷新stdout，再更新状态；若管道关闭或写出失败，状态游标与已发现ID保持不变，可重试同一快照。该顺序以安全重试优先，状态保存失败时调用方可能收到重复链接，因此下游应继续按来源ID去重。错误状态不保存文件路径、HTML内容或异常原文。

当前离线工具只支持无查询参数/片段的同源详情URL，以及无查询参数/片段的`rel="next"`链接。含查询参数或片段的链接会被忽略，防止把临时令牌写入结果；分页回环按校验后的来源页身份比较，忽略scheme/主机大小写、DNS尾点、默认443端口及空路径/根路径差异；路径中的未保留字符百分号编码会解码（如`%70age1`等同`page1`），原始Unicode路径按UTF-8百分号序列规范（与HTTPX请求路径一致），保留路径大小写和保留字符语义（如`%2F`不等于`/`）；孤立surrogate拒绝。状态检测到下一页回到已访问页面时会清空游标并报告`pagination_loop`；导航、推荐、表单、脚本、隐藏区和折叠详情主体中的链接会过滤。

数据库按采集目标保存版本化分页状态：已发现ID、最近/下一页、访问页、错误类别/重试次数，以及当前扫描轮次/已见ID/累计完整轮次。状态API的PUT要求revision匹配，最多2 MB，并拒绝下一页与最近成功页或已访问页的等价写法相同；该API只保存操作员提供的状态，不会自行访问网站或推进分页。

在线Worker现可处理已登记的列表目标：每轮最多访问5个列表页、暂存20个详情页候选；超过上限时保留续页游标，详情失败时回到对应列表页重试，并用已发现ID跳过已完成的详情。每个成功解析的列表页会以内容寻址方式保存原始HTML，并按采集目标记录挂牌ID首次/最近观察时间、出现次数、首末列表页证据SHA-256及存储路径。即使许可在本列表页已保存、但第一个详情尚未暂存时被撤销，也会持久化当前扫描轮次、活动状态、重试页和列表页已观察ID。连续2次完整分页遍历都未见的记录转为`pending_review`；遇到列表/详情失败、策略或robots阻断、页数/详情数上限、分页回环/歧义时，本轮不计入完整遍历。重新发现会将缺失连续次数清零；已进入人工核验队列的状态不会被自动清除，也不自动改变正式挂牌状态。认证接口`GET /api/collection/discovery-observations`支持按来源、采集目标、核验状态过滤并分页读取。

人工可对`pending_review`记录追加`still_listed`、`confirmed_withdrawn`或`inconclusive`结论及可选备注；接口保留复核历史并把观察队列状态设为`reviewed`，**不会修改正式`source_listings.status`**。挂牌随后重新出现时观察状态回到`active`，既有核验记录仍可查询。来源全局开关、策略和robots检查仍须通过；当前在线采集保持关闭。迁移007–009、Worker与API已在本机一次性PostgreSQL 16上通过集成回归；这不替代NAS PostgreSQL 17/生产代码验收。

仍未实现的是人工核验管理界面、独立待发现URL队列及真实站点列表选择器。分页与候选流程只经合成页面验证；须先取得来源许可和获准真实页面样本，再校准分页模板。数据库游标和Worker实现不构成来源授权或P0-09验收完成。

## 状态文件单元测试

状态文件读写模块仅依赖标准库和共享来源URL校验，可在缺少BeautifulSoup/pytest时运行：

```bash
python3.12 -m unittest discover -s tests -p 'test_discovery_state_stdlib.py' -v
```

该命令验证状态schema、兼容回填、大小/软链接/非普通文件/URL拒绝、失败游标保存，以及CLI续页/ID去重/失败重试/分页回环流程。CLI流程使用替身`discover_listing_links`，不验证BeautifulSoup实际解析出的详情/分页链接。
